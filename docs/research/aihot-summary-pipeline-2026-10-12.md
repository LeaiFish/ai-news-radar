# AIHOT 摘要实现与本项目差距

核对时间：2026-10-12。AIHOT 源码版本：652bd6bf4190df0030824dd86a982ea96f5623d5。

## 已确认的流程

- `packages/backend/src/content/extract.ts`：抓取文章 HTML，用 Readability 提取正文；失败后尝试 Jina。无法确认正文时不把错误页面当文章。
- `packages/backend/src/editorial/analyze.ts`：后台 `runSummarize` 调用模型生成中文标题、摘要，保存分析结果。正文不足时不写摘要；中文短帖可直接保留原文。
- `industry/prompts/summarize-article.md`：摘要通常 80–160 字，最多三句；信息少时允许更短。数字、版本和功能必须有原文依据。
- `industry/prompts/summarize-article-empty.md`：明确要求原文为空时返回空摘要，不根据标题脑补。

因此，AIHOT 的摘要来自正文处理和后台写作，不是浏览器临时翻译，也不保证每条无正文消息都有摘要。

## 本项目现状

`scripts/update_news.py` 的 `fetch_aibase` 只读取列表标题、链接、时间，未获取详情正文或摘要。现有翻译补全只处理标题；`scripts/build_topics.py` 只传递已有摘要，不能生成新摘要。

当前公开主题快照：豆包 39 条中 33 条缺摘要；千问 82 条中 61 条缺摘要；Kimi 28 条中 15 条缺摘要。统计包括主题文件全部已收录历史记录，不是仅近30天。

## 建议实现

1. 先保留 RSS/API 已提供的摘要和正文片段；按原文 URL 复用已有公开摘要，避免重复采集。
2. 对近30天公司主题中缺摘要的记录，后台有界抓取允许的公开文章详情。拒绝私网地址、非 HTTP(S) 地址及跳转到私网；限制正文大小、超时和每轮数量。
3. 对可确认的正文生成中文摘要，沿用现有模型配置；只发送公开新闻标题和正文。按 URL、正文哈希和提示词版本缓存摘要，更新正文时失效。
4. 分别标记来源摘要和模型摘要。正文不可得、付费墙、生成失败时留空并记录状态，不把标题扩写冒充正文摘要。
5. 先以豆包/Kimi 的小样本验证事实、数字和公司归属，再扩展。浏览器只读取生成好的摘要，不直接携带 API Key 调用模型。

正文抓取与模型摘要是后续功能；本次仅完成研究、时间轴对齐和删除重复原文按钮。没有读取本地内部指标文件，也没有新增正文抓取或付费摘要调用。
